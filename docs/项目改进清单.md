## 9. 附录 A：面试问答准备（按当前代码的真实情况）

| 面试官可能问 | 你该怎么答（基于现状） |
| --- | --- |
| 为什么拆 Java + Python 两个服务？边界怎么划？ | 业务与状态在 Java，AI 能力（embedding/向量检索/LLM/搜索）在 Python；HTTP + JSON 契约，OCR/LLM/搜索都通过接口抽象以便替换。**补充一句**：现在回头看，如果 AI 侧只有一次 LLM 调用，不必拆服务——是"语义去重需要本地模型常驻内存"这一点才让独立部署真正合理。 |
| 去重阈值 0.92 怎么定的？ | **诚实答**：初版凭经验取 0.92，实测改写句 0.9348 仅勉强过线，说明阈值偏紧；正确做法是用标注样本画阈值敏感性曲线（P4-44）。`IndexFlatIP` + 向量归一化 = 余弦相似度，比 `IndexFlatL2` 更适合语义相似。 |
| FAISS 单机持久化在多 worker 下会怎样？ | 现在是**有坑的**：`_save` 无锁、非原子写，多 worker 会互相覆盖；方案是原子替换 + 单写者（队列或独立写进程），数据量大再迁 Qdrant/Milvus。**主动暴露这个坑反而加分。** |
| Java 读超时 60s，Agent 最坏 260s，怎么处理？ | 这是设计缺陷。修法是给 Python 侧加总预算 deadline（如 45s），Java 超时留余量（如 300s），并把超时契约写进接口文档。 |
| 站内信 + 结论版本留痕怎么保证一致？ | 目前**缺事务**，是已知问题，修法是 `@Transactional`。说明你知道多表写入要原子。 |
| ThreadLocal 为什么要清理？ | Tomcat 线程复用，不清理会串号/内存泄漏；正确位置是拦截器 `afterCompletion`。**（当前代码没做，如实说）** |
| 热度榜为什么用 ZSET？衰减为什么用 Lua？ | ZSET 天然按分数排序、Top10 读取毫秒级；衰减需要"遍历全部成员改分 + 清理低分"，放 Lua 里保证原子且减少网络往返。 |
| LLM 返回非法 JSON / 遇到提示词注入怎么办？ | **这是你的加分题**：`_extract_json` 已做代码块剥离与首尾截取；注入方面你在测试数据里埋了样本但还没做防护，可以现场讲清设计方案（证据分隔符 + 系统指令声明 + 输出枚举校验 + 不合法转人工）。 |
| 如果 AI 服务挂了，系统怎么退化？ | Java 侧 `@Async` 失败写 `status=3` 检测失败可重试；但当前存在"LLM 失败被当成转人工"的语义混淆（P2-19），这正是要修的。 |
| 这个项目你觉得最大的不足是什么？ | 答"工程交付"而不是"功能"：没有测试、没有 CI/Docker、文档与实现有偏差。这个回答比硬撑要好得多。 |
