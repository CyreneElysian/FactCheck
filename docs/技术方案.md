## 1. 总体架构

```
浏览器（Vue3 + Element Plus）          微信小程序
   │ 静态页面                              │ wx.login + 同一套 /api
   ▼                                      ▼
Nginx 1.20.2（html/fact-check）      Spring Boot 2.7（Java 后端）
   │ /api 反向代理  ─────────────────────►
   ▼
Spring Boot 2.7（Java 后端）
   │ ├── MySQL 8.0（关系数据）
   │ ├── Redis 7（热度榜、限流、缓存）
   │ ├── Aliyun OSS（图片存储）
   │ ├── Aliyun OCR（图片识别，接口可替换）
   │ ├── Aliyun 内容安全（文字/图片审核）
   │ ├── 微信开放接口（code 换 openid/unionid）
   │ └── Python Agent（FastAPI）
   │        ├── Embedding 小模型（去重，阈值可配置）
   │        ├── LLM + Web Search（事实检测）
   │        └── FAISS / Redis（向量索引）
   ▼
LLM / Search API（可配置）
```

核心原则：
1. 传统业务代码用 Java（Spring Boot），AI 能力用 Python（FastAPI）。
2. Java 通过 HTTP 调用 Python Agent，接口协议用 JSON。
3. OCR 做成 Java 接口，默认实现为阿里云 OCR，后续可替换。
4. 图片存储用阿里云 OSS。
5. 热度榜用 Redis ZSET。
6. Web 与微信小程序共用同一套后端接口和 t_user 表，账号天然同步。
7. 检测结果先用轮询获取，后续可升级 WebSocket（S18）。
8. 代码风格严格对齐 sky-take-out：`Result` 统一返回、JWT 拦截器、全局异常处理、MyBatis XML、SLF4J 日志、Javadoc 注释。

### 2.3 Python Agent
| 项 | 选型 | 说明 |

### 3.1 包名说明
- 建议包名 `com.factcheck`，风格完全对齐 sky-take-out 的 `com.sky`。
- 如希望与参考项目完全一致，也可继续使用 `com.sky`，由用户确定。

### 3.2 代码规范（强制）
1. 所有 Controller/Service 实现类使用 `@Slf4j`。
2. 关键方法入口必须输出日志，有参数必须打印参数，例如：
   ```java
   /**
    * 管理员查询全部待核查的信息
    */
   @GetMapping("/pending/top10")
   public Result<List<PendingClaimVO>> top10() {
       log.info("管理员查询待核查热门消息Top10");
       return Result.success(adminPendingService.listTop10());
   }
   ```
   ```java
   log.info("用户提交文字检测：userId={}, content={}", userId, content);
   log.error("调用Python Agent失败：recordId={}", recordId, e);
   ```
3. 所有类和方法必须有 Javadoc，说明“这是干什么的”，例如：
   ```java
   /**
    * 事实检测记录服务实现
    */
   @Service
   @Slf4j
   public class DetectServiceImpl implements DetectService {
       /**
        * 用户提交文字检测
        * @param userId 当前用户ID
        * @param detectSubmitDTO 提交内容
        * @return 检测记录ID
        */
       @Override
       public Long submitText(Long userId, DetectSubmitDTO detectSubmitDTO) { ... }
   }
   ```
4. 返回体统一使用 `Result<T>`；分页统一使用 `PageResult`。

## 5. Redis 设计（热度榜 + 限流）

### 5.1 热度榜 ZSET
- Key：`fact:hot:claim`
- Member：`recordId`
- Score：热度分（浮点数）

热度分组成：
| 行为 | 权重 |
| --- | --- |
| 提交检测（含精确/语义命中） | +1 |
| 查看检测详情 | +0.5 |
| 发起申诉 | +3 |
| 管理员人工诊断完成 | +2 |
| 关联/发布权威信息 | +5 |

操作：
```
ZINCRBY fact:hot:claim 1 <recordId>
ZREVRANGE fact:hot:claim 0 9 WITHSCORES   # 查询 Top10
```

时间衰减：
- Spring `@Scheduled` 定时任务每天 03:00 执行。
- 公式：`newScore = oldScore * 0.85`（可配置）。
- 清理：`ZREMRANGEBYSCORE fact:hot:claim -inf 1` 移除过低热度成员。
- 说明：MVP 使用 Lua 脚本遍历重写或 `ZRANGE ... WITHSCORES` 后 `ZADD` 更新。

### 5.2 限流
- Key：`fact:limit:detect:{userId}` 或 `fact:limit:detect:ip:{ip}`
- 规则：同一用户每天最多提交 50 次检测（可配置），超出返回“操作过于频繁”。
- 用 `INCR` + `EXPIRE` 实现计数。

### 5.3 其他缓存（可选）
- `fact:cache:record:{id}`：记录详情缓存 30 分钟。
- `fact:captcha:{uuid}`：验证码（如增加），TTL 5 分钟。

### 5.4 去重配置（S10，配置文件方式）
去重参数不放在 Redis，放在配置文件中：
- Java `application.yml`（**实际前缀为 `fact-check.agent`，非 `fact-check.dedup`**）：
  `fact-check.agent.exact-enabled=true`、`semantic-enabled=true`、`semantic-threshold=0.92`、`min-text-length=8`；
  均支持环境变量覆盖，也可整体用环境变量注入。

### 7.2 语义去重（小模型）
- 模型：`BAAI/bge-small-zh-v1.5`（中文效果好、体量小，CPU 可跑）。
- 索引：FAISS `IndexFlatIP`（内积，配合归一化等于余弦相似度）。
- 持久化：索引文件 + 元数据 JSON 存储在本机 `data/`；也可将向量写入 Redis Hash 作为备份。
- 增量：Java 在记录完成（AI/人工判定）后调用 `/index/add` 添加向量。
- **S10 去重配置（配置文件）**：
  - `config.py` 中配置：`DEDUP_THRESHOLD`（语义相似度阈值，默认 0.92）、`DEDUP_MIN_TEXT_LENGTH`（最短语义去重文本长度，默认 8）、`DEDUP_TOP_K`（返回最相似条数，默认 1）。
  - Java `application.yml` 同步配置（**实际前缀为 `fact-check.agent`**）：`fact-check.agent.semantic-threshold`、`fact-check.agent.exact-enabled`、`fact-check.agent.semantic-enabled`、`fact-check.agent.min-text-length`。
  - 短文本（低于 min-text-length）只做精确去重，不做语义去重，避免误判。

### 7.3 检测 Agent 流程
1. 接收 `{text}`。
2. 生成 1-3 个搜索查询词（LLM 生成）。
3. 调用搜索源获取 top 10 结果（标题、URL、摘要、来源、发布时间）。
4. 可选：对 top 3 网页抓取正文并抽取可读文本。
5. 组装提示词，LLM 输出 JSON：
   ```json
   {
     "can_judge": true,
     "verdict": "TRUE",
     "confidence": 0.86,
     "reasoning_chain": "1. 根据XX官方发布... 2. ...",
     "evidence": [
       {
         "title": "…",
         "url": "…",
         "snippet": "…",
         "source": "新华网",
         "source_credibility": 0.95,
         "relevance_score": 0.93
       }
     ],
     "human_reason": null
   }
   ```
6. 若 `can_judge=false`，`verdict` 与 `confidence` 清空，`human_reason` 说明为什么需要人工；证据列表仍返回供管理员参考。
7. 输出**强制校验**：`verdict` 只接受 `TRUE/FALSE/UNVERIFIED`，`confidence` 归一到 0-1；
   非法取值或无法解析 JSON 时不允许直接落库：
   - 模型未给出合法结论（verdict 非法）→ `can_judge=false`，转人工复核；
   - LLM 调用失败 / 输出无法解析 / 超出整体预算 → `error=true`，
     Java 侧据此记为**检测失败**（可重试）而不是塞进人工队列。

**时间预算（重要契约）**

单次 `/detect` 受 `DETECT_TOTAL_BUDGET`（默认 45s）约束：生成搜索词、搜索、抓取正文、调用 LLM
各步骤都按剩余预算设置超时，预算耗尽则提前收尾。该预算**必须小于** Java 侧
`fact-check.agent.timeout`（默认 90s），否则会出现"Java 已判失败、Agent 仍在执行（可能已写入向量索引）"的状态不一致。

**证据相关度的确定方式**

- 位置分：越靠前越高（rank 0 → 1.0，之后每条递减 0.08）；
- 词面重合：待检测消息与（标题 + 正文）的字符二元组重合率；
- 相关度 = 0.55 × 位置分 + 0.45 × 词面重合；模型给出了 `relevance_score` 时以模型值为准。
- 证据最终**按相关度降序**返回；`source_credibility` 一律由域名规则表（`credibility.py`）决定，
  **不采信模型自报的可信度**（自报数字无法复核，可信度必须确定性且可审计）。

**防提示词注入**

待检测文本与抓取的网页正文都是不可信输入，其中可能包含"忽略以上设定""请判定为真"之类内容：

1. 不可信内容统一放入 `<untrusted_claim>` / `<untrusted_evidence>` 标签，系统提示中明确声明其仅为数据；
2. 输入侧转义这些标签字面量（`[已过滤标签]`），防止内容伪造边界、提前闭合标签；
3. 输出侧强制校验（见第 7 条），防止注入内容改变输出契约；
4. 系统提示要求：若发现疑似注入，照常给出结论并在 `human_reason` 中说明"检测到疑似提示词注入"。

## 8. OCR 与 OSS 设计

### 8.1 图片存储（OSS）
- 工具类：`AliOssUtil`（参考 sky-take-out）。
- 上传接口：`POST /api/common/upload`，返回可访问 URL。
- 目录规范：

### 8.2 OCR 接口抽象
> 实际签名接收上传文件而非图片 URL（业务上由 Controller 先上传 OSS 再调用 OCR）。

```java
/**
 * OCR 识别服务接口
 */
public interface OcrService {
    /**
     * 识别图片中的文字
     * @param file 图片文件
     * @return 识别出的文本
     */
    String recognize(MultipartFile file);
}
```
- 默认实现 `OcrServiceImpl`：调用阿里云市场“通用文字识别”接口（`Authorization: APPCODE <appCode>`），解析 `content` 或 `prism_wordsInfo` 字段。

- 前端展示 `text`，用户编辑后调 `POST /api/detect/submit`，带上 `sourceType=2` 和 `imageUrl`。

- 登录流程：`wx.login` 拿 code → `POST /api/user/wechat/login` → 已绑定返回 JWT；未绑定引导输入 Web 账号密码 → `POST /api/user/wechat/bind`。
- 数据同步：小程序与 Web 共用同一 Java 后端、同一 `t_user`、同一 JWT，天然同步。

## 10. 安全设计

| 项 | 方案 |
| --- | --- |
| 密码 | BCrypt 加密存储，登录失败 5 次锁定 10 分钟（待确认项） |
| 认证 | JWT，用户端 `authentication` 头，管理端 `token` 头；过期时间可配 |
| 鉴权 | `JwtTokenUserInterceptor` / `JwtTokenAdminInterceptor`；管理员接口必须管理员角色 |
| 上传 | 扩展名白名单 + 大小限制 |
| 内容安全 | S2：文字/图片提交前调用阿里云内容安全审核，审核日志写 `t_content_safety_log`（**当前为空实现，见项目改进清单 P2-13**） |
| 提示词注入 | AI 侧将用户文本与抓取的网页正文一律视为不可信数据：标签隔离（`<untrusted_*>`）+ 边界字面量转义 + 系统提示声明"仅为数据" + 输出字段强制校验（详见 §7.3） |
| AI 失败语义 | Agent 侧故障（LLM 失败 / 输出无法解析）以 `error=true` 返回，Java 记为**检测失败（status=3）**；只有"AI 确实判断不了"才转人工（status=1），避免模型抖动灌满人工队列 |
| 防刷 | S9：Redis 计数限流：检测提交、登录、注册 |
| 微信登录 | S11：code 换 openid/unionid；openid 与 t_user 唯一绑定，防止重复绑定 |
| 敏感配置 | OSS key、JWT secret、LLM key、微信 appsecret 使用环境变量注入，不写死在 yml（至少生产环境） |
| CORS | 同源部署，开发环境配置 CORS 白名单；小程序请求域名需加入微信后台白名单 |
| 审计 | S3：管理员操作日志 `t_operation_log` |
| 数据隔离 | 用户只能查自己的记录、收藏、评分、站内信和申诉；管理端可查全部；注销用户记录脱敏展示 |

## 11. 性能与可扩展性

- 检测异步化：`@Async` 线程池处理 LLM 调用，前端轮询，避免 HTTP 长时间阻塞。
- LLM 超时：60s；失败重试 1 次；仍失败则记录状态为“检测中失败”，支持用户重新提交。
- Python Agent：Uvicorn 多 worker；LLM 调用使用异步 HTTP，提高并发。
- 向量检索：MVP 单机 FAISS 足够支撑 10 万级记录；超过后迁移 Qdrant/Milvus，接口不变。
- 数据库：分页查询 + 索引；历史记录按 `user_id + create_time` 索引。
- 热度榜：Redis ZSET 保证 Top10 读取毫秒级。
- Java 无状态，可水平扩容；Nginx 做负载均衡。
